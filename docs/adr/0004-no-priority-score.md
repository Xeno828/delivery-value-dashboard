# Intake returns delivery consequence, never a priority score

The obvious thing to build here is WSJF, or value-over-effort, or any of that family — and we deliberately did not. Every one of them multiplies an unvalidated value estimate by an unvalidated size estimate and presents the product as arithmetic, which launders a judgement into a number that is then very hard to argue with in the room.

What is genuinely computable is the delivery consequence of an ordering: what each sequence of asks costs the others in working days. That is returned. The relative worth of competing asks stays with the people accountable for it.

Expect this to be re-proposed; the rejection is the decision. See `docs/product-intake.md`.
